## Axis labels

Keep `categories` complete: they name each point and label the table rows. To thin or shorten the x-axis, use `xTickFilter` and `formatXTick`, which only affect the ticks:

```tsx
<LineChart
  series={[{ name: "Visitors", data: visits }]}
  categories={days} // "2026-09-01" … "2026-09-30"
  xTickFilter={(i) => i % 7 === 0}
  formatXTick={(day) => day.slice(5)} // "09-01"
  title="Visitors in September"
/>
```

Only the first and last categories anchor to the plot edges; every other tick centres on its point.

## Dates

`categories` are evenly spaced, which is right for steps like weeks of a course or survey waves. For dates, pass `x={timeAxis(dates)}` instead. Points are then spaced by elapsed time, so irregular dates are drawn at their real distance apart. The data below is missing 9–11 September:

<Example
  code={`import { LineChart } from '@eekodigital/raster';\nimport { timeAxis } from '@eekodigital/raster/time';\n\n<LineChart\n  series={[{ name: 'Views', data: views }]}\n  x={timeAxis(days, { interval: 'day' })}\n  labels={{ locale: 'en-GB' }}\n  title="Daily views"\n/>`}
>
  <LineChartDatesDemo client:load />
</Example>

`timeAxis` lives at `@eekodigital/raster/time` (about 1 KB), so charts with categories don't carry date code.

- **Values** are `Date`s, ISO strings or epoch milliseconds, in ascending order, one per data point. Date-only strings like `"2026-10-03"` are UTC midnight.
- **Ticks** fall on calendar boundaries: days for short ranges, Mondays for medium ones, then months, quarters and years, chosen to fit the width. Month ticks name the year on January and on the first tick.
- **Gaps:** `interval` (`"day"`, `"week"`, `"month"`, `"quarter"` or `"year"`) is the data's cadence. Where a point is more than one interval after the previous one, the line and area break. Without it, the line joins every point.
- **Time zone:** ticks and names use UTC unless you pass `timeZone`, e.g. `"Europe/London"`. Server and client render the same thing, because the zone is named rather than taken from the machine.
- **Names:** points, the summary and the data table use the long date in `labels.locale`: "Views, 3 October 2026: 42, 3 of 12" in `en-GB`, "October 3, 2026" in `en`. Points that aren't at midnight add the time. Pass `format` (`Intl.DateTimeFormatOptions` or a function) to change it. The table's first column is headed `labels.dateColumn` ("Date").

`xTickFilter` and `formatXTick` apply to categories only. `xLabelMinSpacing` sets the minimum px between date ticks, which `timeAxis` otherwise estimates from the width of the locale's labels.

For large series, create the axis with `useMemo` so its formatting and gap checks aren't repeated on every render: `const x = useMemo(() => timeAxis(days, { interval: "day" }), [days])`.

## Reference lines

`referenceLines` draws dashed, labelled lines for targets, thresholds and goals. The value scale stretches to include each line.

<Example
  code={`<LineChart\n  series={[{ name: 'Assessed', data: [10, 25, 40, 60, 72, 86] }]}\n  categories={['Week 1', 'Week 2', 'Week 3', 'Week 4', 'Week 5', 'Week 6']}\n  referenceLines={[{ value: 80, label: 'Target' }]}\n  title="Assessment progress against target"\n/>`}
>
  <LineChartReferenceDemo client:load />
</Example>

- **Vertical lines:** with a [date axis](#dates), `{ value: "2026-10-05", label: "Launch", axis: "x" }` draws a vertical line at that date. A date outside the data's range is left out. Categories have no in-between values, so they don't take x lines.
- **Accessibility:** the line isn't focusable, and its SVG label is hidden from assistive technology. The same text is at the end of the summary ("… Target: 80.") and in the table caption ("Data for … Reference line: Target: 80."). Reword both with `labels.referenceLine` and `labels.referenceNote`.
- **Styling:** the colour is `--raster-reference`, falling back to `--raster-text-subtle`. The line keeps its dash in forced-colours mode, so it stays distinct from series lines.

## Large series

Above 200 points in a series, LineChart switches to dense mode. Each series is drawn as one path, downsampled to the first, lowest, highest and last point in each pixel column (which looks the same), with no per-point marks. At 1,000 points that takes the server HTML from about 310 KB to about 62 KB, and the SVG from 261 KB to 13 KB.

<Example
  code={`<LineChart\n  series={[\n    { name: 'Views', data: views },       // 730 days\n    { name: 'Visitors', data: visitors },\n  ]}\n  x={timeAxis(days, { interval: 'day' })}\n  title="Daily traffic, 2025–2026"\n  selectedIndex={selected}\n  onSelect={setSelected}\n/>`}
>
  <LineChartDenseDemo client:load />
</Example>

- **One control.** The chart has a single focusable slider (a visually hidden `<input type="range">`). Its name is the series, and `aria-valuetext` names the current point, e.g. "Views, 3 October 2025: 512, 276 of 730". Screen readers announce each change, NVDA switches into focus mode so the arrow keys reach the chart, and VoiceOver on iOS can swipe through the points.
- **Same keys** as other charts: ← / → point, Home / End, PageUp / PageDown 10 points, ↑ / ↓ series, Enter / Space select (", selected" is added to the value), Escape clear.
- **Marker:** the current point shows a marker with the focus ring while the slider has focus. Pointing anywhere over the plot moves it to the nearest point and shows the tooltip; clicking selects that point.
- **Still in the HTML:** the summary and the data table, so every value is available without JavaScript.
- `curve="smooth"` is drawn straight in dense mode, because curves can't be seen at that density and cost about three times the bytes.
- `dense={false}` keeps per-point marks, `dense` forces dense mode, and `dense={500}` changes the threshold.

## Accessibility

- A `role="figure"` named by the visible `title` and described by a generated summary (chart type, series and point counts, range).
- The SVG is a `role="group"` with `aria-roledescription="chart"`; no `graphics-*` roles.
- Each series is a `role="group"` named `{series}, {n} points`.
- Each point is labelled `{series}, {x}: {y}, 3 of 12`. With `onSelect`, `selectedIndex` or a click handler, marks are `role="button"` with `aria-pressed`; otherwise they're static `role="img"`.
- Points use a different marker shape per series (circle, square, triangle…) as well as colour.
- A visible **Show data table** button (`aria-expanded`) reveals a real table captioned `Data for {title}`, with `th scope` headers and values run through `formatValue`.
- Escape (inside the chart only) clears the selection and announces it in a polite live region; it doesn't close a surrounding dialog.
- Animations stop under `prefers-reduced-motion`. In forced-colours mode marks use system colours, told apart by dash pattern and marker shape.

| Key               | Action                               |
| ----------------- | ------------------------------------ |
| ← / →             | Previous / next mark                 |
| Home / End        | First / last mark                    |
| PageUp / PageDown | Back / forward 10 marks              |
| ↑ / ↓             | Previous / next series               |
| Tab               | Leave the chart (one tab stop)       |
| Enter / Space     | Toggle selection (interactive marks) |
| Escape            | Hide the tooltip and clear selection |

See the <a href="/guides/accessibility/">Accessibility guide</a> for the shared structure, the `labels` prop and screen-reader testing.
